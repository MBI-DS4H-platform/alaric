Please write an efficient script for an identity filter on two organized pose dirs.

The algorithm is as follows.
1. For both pose dirs, glob all files and inspect all headers. Verify that the bucket size is the same. Store in a file index for each file the bucket and the mini buckets: O and C. Build an offset index I as the cumsum of C. 
2. Build a set of buckets that are present in both pose dirs. Discard all file index entries in both pose dirs with buckets that are not in this set.  
3. For each pose dir, calculate the grand sum of nP over all files that are still in the file index.  
4. Iterate over each bucket. Build a sorted array A of mini-buckets that are present in both pose dirs for that bucket. Then, for each file index of that bucket, build an A-range: for the first mini-bucket in the file's O, determine the index in A (if it is not in A, proceed to the second, third, etc.) and do the same for the last mini-bucket (if it is not in A, proceed to the second-to-last, etc.) . Since both O and A are sorted, all entries in O will fall into this A-range.
5. Iterate for each file F in the smallest pose dir (as computed in step 3). Load the poses of this file . Then identify all files from the other pose dir with the same bucket and some overlap in the A-range, store these in the list L. Iterate over all mini-buckets in F, skip those that are not in A. For each mini-bucket, make sure that all files in L that have this mini-bucket are loaded. Normally there should be only one such file; if there are more than one, the mini-bucket has been split and can be reconstituted (in sorted form) by concatenation (files have an ordering, pose-1 comes before pose-2, the concatenation respects the same ordering). The result is two sorted arrays of the same mini-bucket, one coming from F, one coming from one or a few files in L. Efficiently find the intersection of these sorted arrays. You may assume that it is orders of magnitude smaller than the two arrays and you can store it in memory as a dict S with (bucket, mini-bucket) keys. Afterwards, you can unload every loaded file in L where the mini-bucket is out of its A-range.    
6. Build a global pose index (based on canonical ordering) for S, uint64. Flush S to disk (output pose dir).
7. Iterate for each file F in each pose dir (as computed in step 3). Keep a global pose index (uint16, starting at 0, increment by nP after each file, but include files that were discarded in step 2; you may want to pre-build the per-file pose index offsets before step 2) Load the poses of this file. Iterate over the mini-buckets (keep track of their global pose offset). Then efficiently build a mask if each pose is present in S. Obtain the positive elements and map them to the global pose index of the corresponding element in S. 
At the end, store the uint64-uint64 mapping to disk. 

As a correctness test (to be added to the test suite), you can run frag4-fwd and frag4-bwd and apply the script on their output pose dirs, and compare this to a brute force approach.
