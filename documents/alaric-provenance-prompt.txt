Please make a script `alaric-propagate-provenance [pool-graph] [representative] [deployer] [--pool-dirs ...] [--branch ...]`. 

The script has two modes.

Mode 1: `pool-graph` + `representative` + `deployer` + optional `--branch`

`pool-graph` is a JSON graph file as generated by `alaric-pool-graph` (NOTE1).

`representative` is one of the representatives in that graph: if that argument is missing or not in the representative list, enumerate that list and exit the program . 

`deployer` is `local` or `remote`.

First, determine the result dir, which is `../CACHE/results` if `local`, else ALARIC_REMOTE_RESULT_DIR.

Then, look up the representative and trace its lineage as a list of pool dirs, ending with a pool dir that has grow provenance (provenance.py) .
If a `merge` pool dir is encountered first, `--branch` must contain one of the upstreams: if not, exit with a message that lists the upstreams and tells the user to use `--branch` to select one.

From the pool dir list, analyze the sigils to find their physical localtions.

If `remote`: a mode 2 `alaric-propagate-provenance` command is synthesized using the computed pool dir locations. the command is written to `propagate-provenance-<representative>.sh` and this file is uploaded in the same way as a `run.sh` by the remote deployer.

Mode 2: `--pool-dirs`

Make sure that all pool dirs exist. The last pool dir must contain grow provenance (provenance.npy or its .zst form). All other pool dirs must contain filter provenance (provenance.npy in e.g. a filter action, map-X.npy in e.g. a merge action). The filter provenance is applied to filter down the grow provenance so that it corresponds to the poses in the first pose dir. The resulting "propagated" grow provenance is written as prop-provenance.npy.zst in the first pose dir.


NOTE1: `alaric-chain` reads the same graph file and performs some of the same logic as `alaric-propagate-provenance`.
